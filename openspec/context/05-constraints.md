# Бизнес-ограничения, данные и безопасность

## Действующие условия

| Условие: формулировка источника | Область применения |
|---|---|
| Управление конференцией на медиамосте должно использовать контракт, согласованный обеими сторонами | `jitsi-control` ↔ `jitsi-videobridge` |
| Мосты разных версий не смешиваются в одном relay | `jitsi-videobridge`, конференция на нескольких мостах |
| При включённой аутентификации клиентская и управляющая стороны должны применять согласованную модель доступа к конференции | `jitsi-web` ↔ `jitsi-control` |
| Создание и сопровождение комнаты конференции требует согласованных прав между управляющей и сигнальной системами | `jitsi-control` ↔ `xmpp-signaling` |
| Межсистемные соединения, передающие учётные данные или медиаданные, должны использовать подтверждённые проектом механизмы защиты | Все межсистемные соединения продукта |
| Продукт обрабатывает медиапотоки, данные участников, метаданные конференции и данные аутентификации; единая классификация и сроки хранения этих данных пока не подтверждены | Данные продукта |
| Изменение общей модели аутентификации, приватности или межсистемного security contract требует явного человеческого review | `jitsi-web`, `jitsi-control`, `jitsi-videobridge` |
| Сообщения об уязвимостях направляются через согласованный закрытый канал, а не через публичные issue | `jitsi-web`, `jitsi-control`, `jitsi-videobridge` |
| Недоступный медиамост не должен использоваться для новых подключений участников | `jitsi-videobridge`, выбор моста |
