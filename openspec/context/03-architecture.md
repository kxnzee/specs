# Architecture context

Здесь фиксируются только общие границы систем и межсистемные контракты. Локальная
структура, технологии, конфигурация и команды принадлежат Code Repositories.

## Компоненты и границы

- `jitsi-web` отвечает за пользовательское взаимодействие и встраивание видеосвязи.
- `jitsi-control` координирует конференцию, участников и выбор медиамостов, но не
  обрабатывает медиапотоки.
- `jitsi-videobridge` принимает и пересылает медиапотоки участников.
- `xmpp-signaling` обеспечивает комнаты и сигнализацию, но не является отдельным
  зарегистрированным Code Repository.

Точные repository identity определяет `openspec-orch.yaml`, а связи систем —
`system-map.yaml`.

## Межсистемные ограничения и инварианты

- Координация конференции и обработка медиапотоков остаются разделёнными между
  `jitsi-control` и `jitsi-videobridge`.
- При конференции на нескольких мостах совместимость relay должна сохраняться между
  всеми участвующими JVB.
- Изменения аутентификации или сигнализации должны быть согласованы на всех сторонах
  затронутого межсистемного контракта.

## Интеграции и контракты

- Клиент использует `xmpp-signaling` для участия в комнате конференции.
- `jitsi-control` использует `xmpp-signaling` для координации участников и доступных
  компонентов.
- `jitsi-web` запрашивает создание или подключение к конференции у `jitsi-control`.
- `jitsi-control` управляет конференцией на `jitsi-videobridge`.
- `jitsi-web` передаёт медиапотоки через выбранный `jitsi-videobridge`.

Конкретные протоколы и точки интеграции зафиксированы в `system-map.yaml`; локальная
реализация проверяется в соответствующих Code Repositories.
