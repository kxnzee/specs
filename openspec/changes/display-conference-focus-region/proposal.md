## Why

Участники и эксплуатация не видят, каким инфраструктурным регионом focus-сервиса
(Jicofo) обслуживается конкретная конференция, что затрудняет диагностику проблем
региональной маршрутизации. Jira Story не предоставлена; источник задачи —
согласованный в этой сессии Daily Intent Brief и последующие ответы пользователя
(зафиксированы в `intake.md`).

## What Changes

- Jicofo (`jitsi-control`) добавляет в ответ создания конференции новое свойство
  `focus-region`, заполненное настроенным значением `jicofo.local-region`, только
  когда это значение непустое; при отсутствии или пустом значении свойство не
  добавляется.
- jitsi-web получает `focus-region` из первоначального ответа создания конференции
  через адаптированную интеграцию с зависимостью lib-jitsi-meet (версия
  зафиксирована/pinned); значение фиксируется один раз при создании конференции и
  не обновляется при последующей миграции focus.
- Компонент `ConferenceInfo` в jitsi-web показывает новый компактный label
  `Conference region: <value>` рядом с существующими элементами строки (тема
  встречи, таймер и др.); подпись выводится через существующую i18n-систему,
  значение отображается verbatim как безопасный React text (без интерпретации как
  разметки).
- Отсутствующее, пустое или не распознанное значение региона означает, что label не
  показывается; ошибка пользователю не выводится.
- Область изменения ограничена веб-клиентом (`ConferenceInfo` в jitsi-web); мобильные
  клиенты вне scope.
- `jitsi-videobridge` не изменяется.

## Capabilities

### New Capabilities
- `conference/region-diagnostics`: отображение настроенного региона focus-сервиса,
  полученного от Jicofo при создании конференции, как диагностического поля в
  информационной строке веб-конференции.

### Modified Capabilities

Нет — изменение не затрагивает требования существующих capability
(`conference/visitor-promotion` и другие).

## Repository Impact

| Repository | Capabilities |
| --- | --- |
| `jitsi-control` | `conference/region-diagnostics` |
| `jitsi-web` | `conference/region-diagnostics` |

Детализация по репозиториям с планируемыми изменениями:

- `jitsi-control` — **implementation**. Ожидаемое изменение: добавление свойства
  `focus-region` в ответ создания конференции при непустом `jicofo.local-region`,
  тесты backend. Причина: источник значения региона.
- `jitsi-web` — **implementation**. Ожидаемое изменение: адаптация интеграции с
  зависимостью lib-jitsi-meet для чтения `focus-region`, обновление типов, UI
  `ConferenceInfo`, i18n-строка для новой подписи, тесты. Причина: отображение
  значения пользователю в веб-клиенте.

`jitsi-videobridge` рассмотрен и явно исключён из Repository Impact: изменений не
требуется, он не участвует ни в передаче, ни в отображении диагностического
значения региона (подтверждено пользователем в Intake). Registry-репозиторий без
планируемых изменений не включается в таблицу Repository Impact.

## Impact

- Контракт ответа создания конференции: добавляется новое опциональное свойство
  `focus-region` (обратно совместимое расширение, отсутствие свойства — валидное
  состояние).
- jitsi-web: адаптируется интеграция с зависимостью lib-jitsi-meet, типы
  клиента, компонент `ConferenceInfo`, добавляется i18n-строка для новой подписи.
- Новых внешних зависимостей не вводится.
- Персистентных данных изменение не создаёт: значение региона существует только в
  рамках текущей сессии конференции и не сохраняется отдельно.
- Аутентификация и авторизация не затрагиваются.
